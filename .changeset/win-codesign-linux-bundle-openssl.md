fix(win-codesign): bundle OpenSSL 3.5 LTS with the Linux `osslsigncode` so it starts on distros without OpenSSL 1.1 (Ubuntu 22.04 and later). The 1.3.x Linux bundles linked the build image's `libcrypto.so.1.1` and `libcurl.so.4` but shipped an empty `lib/`, because `bundle-osslsigncode-libs.sh` copied the libraries next to the output zip instead of into the directory being zipped, so the binary failed with "libcrypto.so.1.1: cannot open shared object file". Linux now uses the same model as macOS: OpenSSL (same pinned version and checksum) built shared with the legacy provider compiled in, libp11's `pkcs11prov` built against it in `lib/ossl-modules`, and `osslsigncode` linked with RUNPATH `$ORIGIN/../lib` (with OpenSSL 3 it no longer needs libcurl). The bundle ships the OpenSSL and libp11 license texts. The build fails if any binary or bundled library needs a non-base-system library that is not in the bundle, has an absolute RUNPATH, or needs glibc newer than 2.31; CI smoke-tests every Linux bundle in a clean `ubuntu:24.04` container (legacy PKCS#12 and PEM file signing, plus SoftHSM-backed PKCS#11 signing on amd64/arm64), and arm64 now builds on a native runner
